# Coverage-guided fuzzing of external targets (#TBD) build plan

> The design and phase plan for extending proptest's **existing** coverage-guided
> fuzz loop (`fuzzWith*`) to drive an **external target process** — a parser, a
> codec, an interpreter, a CLI, a compiler — using that process's own coverage as
> the corpus-admission signal. The loop, corpus, IR mutators, shrinker, and report
> already exist and are in-process; this plan makes the **coverage source pluggable**
> and adds the **target-execution model** (input delivery, oracle, limits) so the
> same loop fuzzes any instrumented binary. The motivating consumer is a Nim-compiler
> campaign (`hunt`), but the design is **target-agnostic by mandate**: a JSON parser,
> a regex engine, or a differential pair must be first-class, not afterthoughts.

## Motivation — the real gap

proptest already has a coverage-guided fuzzer. `fuzzWith` evolves an IR corpus, admitting a mutant when `covAfter > covBefore` and retaining falsifications (`fuzz.nim:243–341`). What it cannot do is fuzz a **separate process**: every coverage read is `currentCoverage()` against the thread-local `{.cover.}` bitmap, which only sees Nim code compiled *into the proptest process*. `hunt`'s target is `nim-<ver>`, a child binary — the in-process bitmap is blind to it; and a generic user's target is *their* binary.

The work is making the existing loop drive an external process:

1. **Make the coverage source pluggable** behind the loop's four `currentCoverage()` reads.
2. **Read an external child's SanitizerCoverage map** soundly — including when the child crashes or is killed.
3. **Model "run the target and judge it"** generically: deliver the input (stdin / argv-file / env), execute under a time/resource limit, and apply a *pluggable oracle* (exit/signal, sanitizer-stderr, differential) — because "what counts as a bug" is the one thing every external consumer customizes.

Everything downstream (corpus, mutators, shrinker, report, `#107`) is reused, generalized over the new seams rather than reimplemented.

## Scope

**In scope (all proptest, all generic):**

1. **A three-type coverage abstraction** (D9): `Coverage` (per-run value), `CoverageProbe` (read a finished run's map — the only execution-mode-polymorphic surface), `CoverageFrontier` (accumulated map + bucketing + the admission decision).
2. **A composable `Target[T]`** (D3) = transport + `InputDelivery` (D13) + `Oracle` (D14) + `CoverageProbe`. In-process and external adapters; `differentialTarget` (D15) composes N targets.
3. **Generalizing `fuzzWith*`** to drive a `Target` + `CoverageFrontier` (D10), default-preserving in-process behavior; `#107` stays decoupled.
4. **The SanitizerCoverage probe + a vendorable multi-TU dump runtime** (`proptest_cov.c`) proptest owns and ships (D1, D5).
5. **Per-run timeouts + resource limits** (D16) — a generic facility, since a random consumer has no `diffmatrix` rlimits underneath it.
6. **The operational phases**: crash de-dup (D11), corpus + frontier persistence/resume (D12), libFuzzer/AFL **corpus directory** import/export and a **crash directory** (D17), per-worker isolation, a coverage summary (D9).

**Out of scope (named so the boundary is explicit):**

- **The instrumented `nim` build** — lives in `hunt`'s matrix toolchain. This plan's tests use tiny instrumented **C** targets, so proptest needs no Nim compiler. (The dump-runtime C snippet itself **is** in scope — proptest owns the runtime half of the ABI.)
- **The grammar generator** (`Strategy[NimProgram]`) — a `hunt` concern, its own RFC. This plan is generator-agnostic.
- **A byte-mutation havoc engine** — not built (D4); a `dictionary` extension point is named for byte-mode consumers.
- **A worker-pool fan-out** — D5/D12 *reserve* per-worker paths so it isn't foreclosed, but the pool itself is a named follow-up (and is unrelated to `parallel.nim`, which solves a different problem).

## Decisions

**D1 — Dual SanitizerCoverage backend, no AFL/libFuzzer dependency.** `-fsanitize-coverage` exists on both compilers but is **not the same facility** (verified in Phase 1a, after the original single-ABI assumption was falsified): clang ships LLVM's full SanitizerCoverage (`inline-8bit-counters`, `trace-pc-guard`, `pc-table`); gcc ships only `trace-pc`/`trace-cmp`. proptest owns the runtime callbacks for both, so it owns the map format and transport. Two `proptest_cov.c` variants, selected at the target's build:
> - **clang backend** (`PROPTEST_COV_CLANG`, `-fsanitize-coverage=inline-8bit-counters`): capture counter-section bounds in `__sanitizer_cov_8bit_counters_init(start, stop)`, **union all init calls** into a region list (multi-TU / shared-library targets call init once per module; capturing one loses coverage), dump the unioned counters. Precise per-edge, no collisions. Link our own `_init` instead of compiler-rt's default sancov runtime.
> - **gcc backend** (`PROPTEST_COV_GCC`, `-fsanitize-coverage=trace-pc`): a bare `__sanitizer_cov_trace_pc()` callback fires at each edge; the runtime keeps a `prev_loc` and folds `(__builtin_return_address(0) >> k) ^ prev_loc` into a fixed-size bitmap (the classic AFL edge-coverage model), then halves `prev_loc`. Multi-TU-free and rebuild-stable (PC-hash, no link-order index), at the cost of hash collisions. Because it hashes **absolute** return addresses, the target must load at a fixed address — built `-no-pie` **or** run with ASLR disabled (Phase 1b pins it at build via `-no-pie`; `externalTarget` disables ASLR per-run as the general story). clang's section-index counters are ASLR-immune, so this is a gcc-only constraint.
Both produce a `uint8[]` map → the **same** wire format (D5), so the probe, frontier, bucketing (D6), and loop are backend-agnostic. clang is the recommended (precise) backend; gcc is the always-available fallback so a gcc-only environment still fuzzes.

**D2 — AFL's external-binary model; `[INV-fresh-exec]`.** We instrument an external binary, run it on an input, read a per-run map — emulating AFL's *model*, not the tool, over sancov. **Load-bearing invariant `[INV-fresh-exec]`: each external run is a fresh process image whose counter section is zero at entry**, so the absolute snapshot (D8) *is* that run's coverage. `externalTarget` guarantees it. A forkserver/persistent target violates it and is out of the absolute-snapshot model — it must supply a probe that zeroes-or-diffs (`CoverageProbe.resetsPerRun`).

**D3 — `Target[T]` is composable: transport + delivery + oracle + probe.** "Run the target and judge it" is one *round trip* but not one *concept*: a JSON-parser fuzzer and a CLI fuzzer share execution and differ only in the oracle. So `Target[T] = object { run*: proc(x: T): Observation[T] }` where `Observation[T] = object { verdict: Verdict; coverage: Coverage }`, and the external constructor *composes* the swappable pieces: `externalTarget(argv, delivery, oracle, probe, limits)`. The oracle is the one seam every external fuzzer customizes, so it is cleanly swappable without rewriting execution/env/covfile/wait. `inProcessTarget(prop)` adapts the existing `proc(x: T)` (run prop, snapshot the in-process probe, map `FalsifiedError`→`vInteresting` at the adapter boundary). `fuzzOnce`/`FuzzOnceResult` stay coverage-free — the kernel is correct; the loop owns coverage. The loop is `fuzz`/`fuzzWith`; the kernel keeps `fuzzOnce` (the `run`/`runOnce` pairing).

**D4 — Coverage feeds corpus *admission*, not directed search.** There is no locality between a generator/IR edit and a target-edge delta, so coverage is the **admission test**: keep an input iff it raised a new edge bucket, so the campaign accumulates a diverse seed set instead of re-exploring the same paths. This is what `fuzzWith` already does in-process (`covAfter > covBefore`); we make admission see the *external* edges. Mutation stays the existing structure-aware `mutateIR*` suite (no byte havoc — bit-flipping a structured input usually makes it invalid). **Byte-mode extension point:** a generic byte target (a protocol/codec) benefits from a `dictionary: seq[seq[byte]]` feeding a `mutateByteDictInsert` op — named here as the byte-mode extension, not built in v1. Honest framing: at low exec rates coverage is a *secondary*, diversity win layered on a good generator, not a substitute for one.

**D5 — File transport: per-run-unique, self-describing, atomic, checksummed, loud.** The map is a file the child dumps; for a slow target the IO is negligible and a file is debuggable. The file is a **versioned, integrity-checked artifact**: header `magic "PCOV" | u32 version | u32 targetId | u32 len`, then `len` counter bytes, then a **trailing checksum** over the counter bytes (so a truncated/poisoned dump is detected, not admitted). The path is **per-run-unique** (`$PROPTEST_COV_DIR/<worker>-<pid>-<iter>.cov`) — this is *correctness*-load-bearing (it defeats the slow-child-late-rename TOCTOU of D7), not merely anti-collision. The child writes to a temp name and `rename()`s (atomic within a dir). A missing / wrong-magic / wrong-version / wrong-targetId / bad-checksum file makes the probe **raise**, never silently return empty coverage (the canonical "looks like it works but is random" trap).

**D6 — AFL 8-bucket classifier over the backend map; order-independent novelty.** The frontier stores **one byte per slot = the bucket id** — a "slot" is a precise edge (clang inline-counters) or a hashed-edge bitmap cell (gcc trace-pc; collisions mean a slot may alias several edges, an accepted fidelity loss for the gcc fallback). `bucketOf` invariant: **`bucketOf(0) == 0` (the unique "unseen" bucket) and `bucketOf(n ≥ 1) ≥ 1`** — any execution outranks unseen, or first-execution edges would never be admitted. Buckets are `{0:unseen, 1, 2, 3, 4-7, 8-15, 16-31, 32-127, 128+}`. Novelty is **order-independent**: an edge is new iff *this run's* bucket for it exceeds the frontier's stored bucket — re-observing at a lower count never flips admission (a precondition for a reproducible corpus trajectory). Phase 2 tests the `0→1` boundary specifically, not only the log boundaries.

**D7 — Dump-on-signal, reap-before-read, hangs are findings.** A target SIGKILL'd on timeout or crashing never runs an `atexit` hook, so the dump runtime installs **async-signal-safe** handlers for `SIGTERM`/`SIGINT`/`SIGSEGV`/`SIGABRT`/`SIGBUS`/`SIGFPE`/`SIGILL` that `write()` the section (captured `start`/`stop` read-only in the handler) + checksum and re-raise; the parent uses **SIGTERM + a grace period** (D16's `perRunTimeout`), escalating to `SIGKILL` after. The parent **`waitpid`-reaps the child (confirms it is dead) before reading** the map, so a still-living child cannot `rename()` after the read; with the per-run-unique path (D5) a late write is harmless. The loop `unlink()`s before each run and treats **absent-after-reap = no-coverage** (never "same as last"). **A memory-corrupting crash can poison the counter section**, so coverage from a crashing run is *advisory* — the verdict (D14) and de-dup (D11), not the coverage, are the source of truth for a crash. A **timeout is a first-class verdict** (`vTimedOut`), not silently dropped — hangs are bugs.

**D8 — Snapshot/reset is a *per-probe* contract, not a universal rule.** sancov from a fresh exec is an **absolute** snapshot → no reset needed; the external probe's `read()` returns this run's coverage directly. The **in-process** `{.cover.}` bitmap is the *opposite*: a session-cumulative accumulator with no per-run snapshot and only a scalar read today. So `inProcessProbe.read()` must **snapshot-and-clear** (reset before the run, return the post-run bitmap as a `Coverage`) — which requires *adding a bitmap-array read to `coverage.nim`* (only `currentCoverage(): int` exists). `CoverageProbe` carries **`resetsPerRun: bool`** so the frontier asserts the model rather than silently miscomputing. "Retires `resetCoverage`" (round-1 claim) was wrong: the in-process path still needs per-run isolation; what changes is the *value-typed* `Coverage` snapshot.

**D9 — Three types; `admit` returns a record, not a bool.** Only *reading a finished run's map* is execution-mode-polymorphic. So: `Coverage` (a value — one run's counters), `CoverageProbe = object { read*: proc(): Coverage; resetsPerRun*: bool }`, and `CoverageFrontier` (shared accumulate/bucket/admit/identity, written once, reused by both probes). `admit(c: Coverage): Admission` where `Admission = object { interesting*: bool; newEdges*, globalEdges*: int }` — folds-and-diffs in one call and feeds the report, the power schedule (`newEdges`), and a coverage summary from one return, killing the "caller sequences two calls" smell. Closures-in-objects per the house style (`Strategy[T]`, `directoryBasedDatabase`).

**D10 — Generalize `fuzzWith*`; keep `#107` decoupled.** The external path is `fuzzWithIR` with `(Target, CoverageFrontier)` in place of `(prop, currentCoverage())`. The default `Target` is `inProcessTarget`, preserving shipped behavior. **`#107` is untouched** — it reads `currentCoverage()` directly in `engine.nim`, not through `fuzzWith`, so it keeps its scalar-delta Pareto objective and this work does not migrate it (avoids engine churn and a cross-phase coupling). Reuse `FuzzReport` (extend **additively** with `CoverageSummary{totalEdges, coveredEdges, newEdgesPerPhase}`; define `coverageHits` = in-process bitmap count vs `globalEdges` = external frontier union so they never drift; **no** colliding `FuzzReport[T]`), `FuzzCorpus`, `mutateIR*`.

**D11 — Crash de-dup: deterministic, shrinker-friendly.** The loop takes `crashKey: proc(o: Observation): string`; **default = the coverage-edge-set fingerprint** (two crashes hitting the same novel edges are likely one bug — generic dedup for free). De-dup is **keep-first-by-key** (matches the deterministic trajectory) or keep-best under a consumer comparator (default: shortest input); it is for *report/storage* dedup and does **not** suppress feeding each distinct crash to the shrinker. `hunt` supplies its ICE-signature oracle; its cross-run `(compiler-commit, signature)` seen-set lives downstream.

**D12 — Persistence: sibling flat-file store; identity includes invocation.** Corpus + frontier + crash set persist target-identity-keyed. The frontier (a flat counter array) and a byte-mode corpus do not fit `ExampleDatabase`'s `seq[ChoiceNode]` shape, so they go to a **sibling flat-file store** (mmap-friendly); the IR corpus and crash reproducers stay in `ExampleDatabase`. `targetId = hash(binary ‖ map-size ‖ backend ‖ dump-ABI-version ‖ consumer-supplied campaignId)` — `map-size` is the clang counter-section size or the gcc fixed-bitmap size; `backend` distinguishes clang/gcc maps of the same target. The **campaignId folds in the invocation** (argv template / relevant env), because the same binary under different flags/env produces different coverage and must not share a frontier (a silent cross-contamination the rebuild-renumber guard would miss). The clang index space renumbers on any rebuild (link-order), so the binary hash guards it; the gcc PC-hash bitmap is rebuild-stable. On a `targetId` mismatch the frontier + coverage annotations are discarded (inputs kept as seeds). The header `targetId` (D5) rejects a stale map in-band.

**D13 — Input delivery is pluggable.** How the child receives one run's bytes is per-target and has no single answer: **stdin** (filters, codecs), an **argv file path** (libFuzzer's `@@` convention, many parsers — hunt's "write a `.nim`, pass its path" is *this*), an **env var**, a **fixed path / named pipe**, or **argv directly** (a CLI arg fuzzer). `InputDelivery = object { plan*: proc(bytes: seq[byte], runDir: string): InputPlan }` returns `(stdin, argv-substitutions, env, temp-files-to-clean)`. Built-ins `stdinDelivery()` and `argvFileDelivery(template)` cover ~90% of targets; hunt is `argvFileDelivery` with a `.nim` suffix, not a bespoke target.

**D14 — Oracle is pluggable; verdict is generic.** `verdict ← exit/signal` (round-1) is only the *crash* oracle and misses most generic bugs — a parser/interpreter exits 0 with *wrong output*; **ASan/UBSan reports are a stderr pattern with exit 0**; a CLI returning 1 on bad input is *not* a bug. So the external target captures `RunResult = object { exitCode, signal: int; stdout, stderr: seq[byte]; timedOut: bool; durationNs: int64 }` and an `Oracle = proc(r: RunResult, x: T): Verdict` maps it. `Verdict = enum vOk, vRejected, vInteresting, vTimedOut`. Built-ins: `signalOracle()` (default — crash/signal/nonzero → `vInteresting`), `sanitizerOracle()` (greps stderr for `==ERROR:` / `runtime error:` — what hunt's O2 needs), `exitCodeOracle(bugCodes)`, `stderrPatternOracle(re)`. The in-process adapter maps `FuzzOnceResult.outcome → Verdict` at its boundary (so neither path leaks the other's result type).

**D15 — Differential / N-target oracle, still a `Target[T]`.** Output-equivalence is the top generic oracle *and* hunt's own O3 (gcc vs clang, encode→decode round-trip, two parsers). `differentialTarget(targets: seq[Target[T]], compare: proc(rs: seq[RunResult], x: T): Verdict)` fans one input across N children and reduces to one verdict — so `Target[T]` is closed under composition and the `fuzz` loop is unchanged. This is the difference between "serves any external fuzzer" and "serves single-process crash fuzzers."

**D16 — Per-run timeout + resource limits, provided by proptest.** A generic consumer has no `diffmatrix` rlimits underneath it, so proptest supplies them: `perRunTimeout: Duration` (drives D7's SIGTERM→grace→SIGKILL — closing that dangling reference) and `ResourceLimits{addressSpaceBytes, cpuSeconds, stdoutBytes}` applied to the child via `setrlimit` (best-effort, POSIX). Without this, D7's timeout machinery has no trigger and the "compiler killed on timeout" case can't be configured. Per-run mechanics live on the `Target`/transport; campaign knobs (`crashKey`, persistence key) extend `FuzzSettings` additively — stated so they don't sprawl across `fuzz` params.

**D17 — Corpus & crash directory interop.** A generic audience lives in the libFuzzer/AFL ecosystem: `importCorpusDir(path)` / `exportCorpusDir(path)` (one byte input per file, content-addressed name) make proptest's external fuzzer a citizen of that world; `exportCrashes(dir)` writes one minimized reproducer per de-duped crash + a sidecar verdict/signature. **Byte-mode only** — IR-mode corpora are strategy-bound and don't interop (an honest, correct boundary). Note the common generic case is `T = seq[byte]` with identity decode (`fuzzBytes`/`fuzzBinary`), so a raw-codec user is never forced to write a `Strategy`.

## Architecture

```
  fuzz(s, target, frontier, settings)  ── generalized fuzzWithIR ──────────────────┐
    corpus(seq[ChoiceNode] | seq[byte]) · mutateIR* · power schedule · crashKey     │
    per iteration:                                                                  │
        x    ← decode(mutate(pick(corpus)))                                         │
        obs  = target.run(x)                  ← Observation{verdict, coverage}      │
        a    = frontier.admit(obs.coverage)   ← Admission{interesting,newEdges,...} │
        if a.interesting: corpus.add ; summary += a.newEdges                        │
        if obs.verdict in {vInteresting,vTimedOut}: retain (de-dup by crashKey)     │
        checkpoint corpus → ExampleDatabase ; frontier → sibling store (D12)        │
  └──────────────────────────────────────────────────────────────────────────────────┘
   Target[T].run ─┬─ inProcessTarget(prop): run prop ; probe(resetsPerRun)=snapshot+clear
                  ├─ externalTarget(argv, delivery, oracle, probe, limits):
                  │     unlink covfile ; deliver(x) ; run child under limits
                  │     SIGTERM+grace+SIGKILL ; waitpid-reap ; RunResult
                  │     verdict = oracle(RunResult, x) ;  coverage = probe.read() (raise if bad)
                  └─ differentialTarget([t1..tn], compare): fan x, reduce RunResults → verdict
   CoverageProbe.read(): Coverage      CoverageFrontier.admit(c): Admission  (bucketed)
   fuzzBinary(s, argv, settings)  =  fuzz(s, externalTarget(argv, stdinDelivery(),
                                          signalOracle(), sancovFileProbe(...), limits), ...)
```

`fuzzOnce`/`FuzzOnceResult` are untouched. The new surfaces are `Coverage`/`CoverageProbe`/`CoverageFrontier`, `Target[T]`/`Observation`, `InputDelivery`, `Oracle`/`RunResult`/`Verdict` — each small and separately testable; the loop is the existing one, re-parameterized.

The ergonomic gradient (house "make the default trivial" value): `prop` → `inProcessTarget(prop)` → **`fuzzBinary(strings(), @["./target"], settings)`** (the 1-line "fuzz this binary on stdin, crash = bug") → `externalTarget(argv, delivery, oracle, probe, limits)` (full control) → `differentialTarget(...)`.

## Testing strategy

The capability is provable without its heavy consumer. Phase 1a is the gating risk (proptest's first C-build/subprocess machinery; `skip`-clean when absent). Phase 1b ships a **checked-in golden dump** so Phases 2–3 never rebuild the C target, and the adversarial fixtures (exit-before-dump, signal, two-TU union) that are the whole point. Phases 2, 4.5, 6a, 6c are pure unit tests over synthetic `Coverage`/`RunResult` and a stub `Target`. Integration determinism (5/6b/6d) drives **deterministic child behaviors** (exit-immediately / `raise(SIGSEGV)` / spin-forever), never timing-dependent ones; the grace period is generous + test-overridable; `unlink`-before-run + absence-means-no-coverage is what makes them flake-free, pinned by a named "SIGKILL → zero coverage, not stale" assertion. Per-test temp-file isolation (unique `$PROPTEST_COV_DIR`, `defer`-cleanup) is designed into Phase 1a and reused.

## Open questions / residual risks

- **gcc vs clang sancov** — *resolved* (Phase 1a verification): `inline-8bit-counters` is clang-only; gcc has only `trace-pc`. Hence the dual backend (D1) — clang precise counters, gcc PC-hash AFL bitmap — rather than one ABI under a `#ifdef`. Both feed the same frontier.
- **Coverage non-determinism in the *real* target** — a target may be coverage-nondeterministic (hash-iteration order, threads). The contract is honest: the loop RNG is seed-reproducible; the *corpus trajectory* is reproducible iff coverage is a pure function of input. An **opt-in** verification re-run (off by default — it doubles cost) sets a `nondeterministicCoverageObserved` flag rather than a mandatory per-iteration check.
- **Worker-pool fan-out** — D5/D12 per-worker paths *reserve* the design; the pool itself is a named follow-up, **unrelated to `parallel.nim`** (which is a linearisability checker, not a worker pool — no reuse there).
- **`targetId` rehash cost** — hashing a multi-GB instrumented binary each resume is slow; a `mtime+size+path` pre-check short-circuits the full hash.
- **Tiny-C-target vs real `nim`** — Phases 1–6 prove the ABI, multi-TU union, transport, signal-dump, oracle, and differential paths; they cannot prove a koch-built `nim`'s early-`quit()`/fork behavior. That validation lives in `hunt` with the instrumented compiler — the one integration gap the proptest tests do not close.

## Relationship to the rest of proptest

This is the **fourth role** of the fuzz/coverage substrate, beside random PBT (`forAll`), in-process coverage-guided PBT (`#107`, untouched here), and the fuzz kernel (`fuzzOnce`) + in-process corpus loop (`fuzzWith*`). It adds no dependency (sancov is a compiler flag) and leaves `fuzzOnce`, `Strategy`, the shrinker, and `#107` untouched — it generalizes the coverage reads behind `Coverage`/`CoverageProbe`/`CoverageFrontier` and adds the composable `Target[T]` (delivery + oracle + probe). Any proptest user fuzzing an external binary benefits — a JSON parser via `fuzzBinary`, a differential pair via `differentialTarget`, a compiler via `hunt`. Persisted fuzz crashes feed the `ExampleDatabase`, so they are available to `forAll`'s regression-replay path like any other saved failure.
