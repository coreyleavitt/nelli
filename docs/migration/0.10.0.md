# Migrating to nelli 0.10.0

A breaking release. It is Wave 3 of RFC-0016 (native-parity hardening): the
undefined-behaviour axis, the build profile in the cache key, the whole-run
check, and the removal of the two fields 0.9.2 deprecated. Read
`docs/migration/0.9.2.md` first if you are coming from 0.9.1; this note covers
only what moves between 0.9.2 and 0.10.0. The full list is in `CHANGELOG.md`.

The walker version moves from `"287"` to `"305"` (§6). Things that break a
build (§2): `SymexSettings.arithChecks` and `SymexResult.fromCache` are gone,
`SymexErrorKind` and `SymexTargetKind` have new members, `UbKind` is wider and
`ubFloatToIntRange` has a new ordinal, `Soundness` has two new fields, and a
few `buildprofile` and admission names moved. Everything else compiles before
and after, which is why this note exists.

## 1. Removals

Both were deprecated in 0.9.2 (INT-39). They are deleted, not deprecated
again.

### `SymexSettings.arithChecks`

What changed: the field, `effectiveArithChecks`, `arithChecksDisagree`, the
`;ac=` / `arithChecks=` cache-key segment and the two `validateSymexSettings`
warnings about it ("arithChecks is empty", "a check is enabled but its
`DefectKind` is excluded") are removed. `ArithCheck` and `arithChecksFor()`
stay: the build-derived set is the one source the walker's gates read.

Why: the build alone decides which arithmetic checks Nim compiled in
(`--overflowChecks`, `--rangeChecks`), and so what the program does. A setting
that disagreed could only describe a program the build does not make, which is
why 0.9.2 tainted such a run `feCheckOption`. The unchecked side is now
answered by the definedness axis (signed overflow, an unsigned or unchecked
zero divisor and `low(T) mod -1` halt as `ub*`), so there is nothing left for
the setting to opt out of, and the `feCheckOption` taint for a disagreeing
setting no longer exists. A drain gated on a check the build does not compile
in returns the path unchanged; the operation's undefined side is the
definedness answer.

What you change:

```nim
# before (0.9.2): opt out of the overflow fork
const s = SymexSettings(integerSemantics: isOptimised,
                        arithChecks: {acDivByZero, acRange})

# after (0.10.0): delete the field. To model checks off, build with them off.
const s = SymexSettings(integerSemantics: isOptimised)
#   nim c --overflowChecks:off ...      # signed overflow now halts (ubSignedOverflow)
#   nim c --rangeChecks:off ...         # the range conversion is not forked
```

Reads become `arithChecksFor(buildSemantics)` (from `nelli/smt/types`):
`acOverflow in defaultSymexSettings().arithChecks` is
`acOverflow in arithChecksFor(buildSemantics)`. `arithChecksDisagree(s)` has no
replacement: it is always false. A `+` merge no longer carries the field, and a
`SymexSettings` literal that names it does not compile. Cached verdicts keyed
with it are orphaned (§6).

### `SymexResult.fromCache`

What changed: the field is removed. `symexFind` takes no `ExampleDatabase`, so
it never served from a cache and the field was always `false`.

What you change: delete the read. If you wanted the cache-hit flag, it is on
the finding: `SymexFinding.fromCache`, set by `symexFindAllWitnesses` and
`symexForAll` when a verdict is served from the database.

```nim
# before: always false
if symexFind(sut, target).fromCache: ...

# after: the cache is symexFindAllWitnesses's
let hits = symexFindAllWitnesses(sut, db).countIt(it.fromCache)
```

## 2. Compile breaks

### `SymexErrorKind`: additions

Diffed between the `v0.9.2` tag and this release. There are no deletions; the
enum only grows, with one reordering inside the `ub*` range (below). The
catalogue is `docs/symex/README.md`, "Declines, taints and undefined
behaviour". An exhaustive `case` over `SymexErrorKind` needs arms for:

- `ubTailUnverified` (K10b): the whole-run definedness gate could not show the
  run defined past the label (an opaque call whose body is foreign, a decline
  or an exhausted budget on the second walk, a lossy witness it cannot
  follow). Fail closed: the `sxSat` stands but is not `trusted()` and replay
  cannot lift it. `classOf` is `dcOmitted`. Appended to `UbKind`.
- `feHostUnadmitted` (K5a): the loaded libz3 is not 4.13.4 or 5.1, or no build
  row covers this build under it. The run decides nothing and is `sxUnknown`.
  `classOf` is `dcNoAnswer`.
- `feUnadmitted` (ADM-1, K7b): a cell with no row in its admission table; a
  decline, never a silent model. `classOf` is `dcOmitted`.
- `feDefectExcluded` (K7b): a `Defect` raise reached the SUT boundary on a
  feasible path and was suppressed by `defectExclusions`. A pure omission
  (`dcOmitted`), so a search it could have answered is `sxUnknown`.

Kinds that exist but are no longer produced: `feFloatWidth` (K2b models the
conversion exactly), `feConvFloatToIntUndefined` (K10a-float answers through
`ubFloatToIntRange`).

The `ub*` range. 0.9.2 declared `ubFloatToIntRange` before
`ubIndeterminateRead`; K10a-axis removed it while it had no producer and
K10a-float added it back at the end. The order is now `ubUnsignedDivZero`,
`ubIntMinModMinusOne`, `ubSignedOverflow`, `ubIndeterminateRead`,
`ubSignedDivZero`, `ubFloatToIntRange`, `ubTailUnverified`, and
`UbKind* = range[ubUnsignedDivZero .. ubTailUnverified]` (was `.. ubSignedDivZero`).
`ubIndeterminateRead` and `ubSignedDivZero` therefore each moved down one
ordinal, and `ubFloatToIntRange` moved to ordinal 5. Nothing persists the
ordinal across releases (the walker number orphans every cache entry, §6), but
a consumer that stored `ord(UbKind)` itself must re-derive it. The `ub*` kinds
stay contiguous, so one `of ubUnsignedDivZero .. ubTailUnverified` arm covers
them.

```nim
# before (0.9.2)
of ubUnsignedDivZero .. ubSignedDivZero: handleUndefined(k)

# after
of ubUnsignedDivZero .. ubTailUnverified: handleUndefined(k)
```

### `stkUndefined` and the `case` sites it breaks

`SymexTargetKind` gains `stkUndefined` (K10a-target, built with
`tUndefined(kinds: set[UbKind] = allUbKinds)`). 0.9.2 told you to add an `else`
arm; an exhaustive `case` on `SymexTargetKind` with no `else` does not compile
until it handles the new member, and the same holds for any `case` on a
`SymexTarget`'s `kind` that reads variant fields (`stkUndefined` carries
`ubKinds`).

```nim
# before
case t.kind
of stkLabel: ...
of stkAssertionViolation: ...
# ... every other member ...

# after: handle it, or keep an else that is right for you
of stkUndefined: report t.ubKinds
```

`tUndefined` searches for an input that reaches undefined behaviour of one of
the listed kinds. `sxSat` carries the witness; `sxUnsat` means none of the
LISTED kinds is reachable, never "no undefined behaviour". The witness is
never run in your process (`hostRunnable` is false) and replay does not run it.
The target is part of the cache key (`Tg<UD:...>`).

Related additions you may meet: `SymexResult.undefined` lists the undefined
sides a run filed under any other target; `ConcolicFlipResult.undefinedReached`
and `FuzzReport.undefinedFindings` (with `formatUndefinedFindings`) carry them
through the concolic and fuzz drivers.

### `Soundness.buildSegment` and `Soundness.buildRow`

`Soundness` gains `buildSegment: string` (the cache key's build and host half
this verdict was decided under, `""` for a record no run stamped) and
`buildRow: string` (the build row it projects onto, `"linux-c"`, `"mingw"`, ...,
`""` when none covers it). A positional or exhaustive `Soundness` construction
needs the fields; a named construction is unaffected. Neither field is stored
with the verdict, because the key already carries it. Read the summary through
`buildSummary(s)`. A `SymexFinding` carries both through `soundness`, and the
JSON render gains `buildSegment` when it is non-empty.

### The build profile and admission names

- `buildprofile.buildSegment` takes the host too:
  `buildSegment(b: BuildSemantics; h: HostSemantics): string`. The old
  one-argument form, `buildFlagsSegment` and `renderBuildFlags` are gone: the
  segment is every field of `BuildSemantics` and `HostSemantics` by
  `fieldPairs`, in place of the separate `|z3=`, `|pcre=` and `|bf=` segments.
- `admitBuild` stays (compile-time half); the host half is `admitHost`.
- `verifiedLibs` / `VerifiedLib` and `varParamMagics` / `VarMagicModel` are
  replaced by admission answers: `admitPcreLib(version, jit)` and
  `admitMagic(magic, site)` return `Admit[P]`. Read it through `admitted(a)`,
  `payload(a)`, `cell(a)` and `decline(a)`. `Admit`'s fields are private; only
  `nelli/smt/admission` and the axis modules construct one.
- `syncConvFloatToIntBoundCond` is removed (the conversion drain is
  `drainConvFloatToIntFresh`, internal).

On the `Admit`-taking IR constructors (ADM-IR): RFC-0016 §8.1 has the
constructor of a keyed-axis IR node take the axis's `Admit` as a proof, so a
parser arm that skips the table does not type-check. This release does it for
the type x memory-op axis:

- `mkZeroValue(zero: Admit[TypeOpModel]; ty: IRType): IRExpr` replaces
  `mkZeroValue(ty)`. `zero` is `admitZeroValue(ty.kind)` (or
  `admitTypeOp(ty.kind, moFieldDefault, toZeroValue)`), imported from
  `nelli/smt/typeaxes`; it asserts the row is admitted and its zero is a
  zero-value node (`zmZeroValue`). A consumer that hand-builds IR with
  `mkZeroValue(ty)` changes that one call; a consumer that only runs the
  parser is unaffected.
- `MemOp`, `MemShare`, `ZeroModel` and `TypeOpModel` now live in
  `nelli/smt/types` (the constructor needs them) and `typeaxes` re-exports
  them, so an import of either module still sees them.
- Building the node with `IRExpr(kind: iekZeroValue, ...)` outside
  `types.nim` is counted by `tests/tsymex_0016_admir.nim` (allowlist zero).

The other keyed axes follow the same rule: the node, or the lowering, that
carries an axis's answer takes that axis's proof.

- Definedness and the magic defect scan. `mkOpaqueCall(callee, retName, args,
  retTy, scan: OpaqueScan; inert, havoc, heapTys, heapAll, raises, why)`
  replaces the version that took `defects: seq[string]` and `undefined:
  set[UbKind]`; the sets are read from `scan`, so the canonical form is
  unchanged. `OpaqueScan` (in `nelli/smt/definedness`, re-exported by `types`)
  has private fields: `noteUndefined(scan, admitDefined(op, class, site),
  profile)` adds an undefined kind from an admitted definedness row,
  `noteMagicDefect(scan, admitMagic(magic, msDef...), name)` a Defect from an
  admitted magic defect row, and `noteDefect(scan, name)` a Defect named from
  the syntax (an index, a variant field, a `raise`; no axis keys these).
  `unscanned` is the scan of an arm that never reads the callee's body. A
  consumer that hand-builds an opaque call passes `unscanned` or a scan it
  filled.
- Stdlib body, float calls. `mkMathCall(math: Admit[StdlibBody]; op, args)`
  replaces `mkMathCall(op, args)`; `math` is `admitFloatCall(op, nargs)`
  (`nelli/smt/stdlib_rows`), the row at `ssFloatCall`, and the call asserts it
  is the row of `op`. The parser now declines a float call whose row is
  declined or absent at parse time (a marker with the row's kind, the
  reason naming its cell) instead of building a node the walker declines at
  walk time. Rows were added for the names the lowering already models and
  had none (`abs`, `min`, `max`, `isInf`, `isFinite`, `isNormal`,
  `toFloat32`, `toFloat64`) and for `nextafter` (declined); an absent name
  declines `feUnsupportedOpAborted`, the kind the lowering reported.
- Pragma and stdlib unchecked scope. `mkArithBlock(proof: ArithScopeProof;
  stmts)` replaces `mkArithBlock(scope, stmts)`. `ArithScopeProof` (`types`)
  has a private scope and three constructors: `arithFromPragma(admitPragma(
  ppRoutine, "overflowChecks", psRoutineDecl))` (`asChecked`),
  `arithFromStdlib(admitStdlibBody(key, ssBodyWalk))` (`asUnchecked`; the row
  must exercise `overflowChecks`) and `arithFromBuild()` (`asBuild`, the
  build's own unchecked arithmetic, which has no table row). `replayArith`
  and `replayScan` are the parser emit's rebuilds of what it already read.
- Magic. No new IR node: a magic lowers to ordinary nodes. `lowerMagic(proof,
  body)` (`nelli/smt/magic_rows`) is the one place an arm's lowering runs, and
  `dispatchMagic` wraps every arm in it with the proof of the arm's row at
  its site (`admitMagic`, or `admitStdlibBody` for an unsigned operator); a
  declined proof asserts. `tests/tsymex_0016_admir.nim` counts `of "<magic>"`
  arms outside a `dispatchMagic` (allowlist zero).
- PCRE is the one axis enforced at its runtime consumer, not an IR
  constructor: there is no IR node for a regex engine (a pattern is a string
  the Z3 string theory or the PCRE engine consumes at walk time), so the proof
  is `admitPcreLib(version, jit)`, asked where the engine is loaded
  (`pcre_engine`), and an unverified library declines with `psUnverifiedLib`.

## 3. New settings

- `SymexSettings.wholeRunDefinedness: bool` (K10b), default `true` (`false`
  under `-d:nelliGateOff`). A trusted `sxSat` needs the whole run defined, not
  only the prefix up to the label: with this on, the winner is checked by a
  second walk from the entry under the witness's model pins, past the label to
  a routine exit. An undefined side the pins do not rule out, an opaque call
  whose body may be undefined, a decline, an exhausted budget or a lossy
  witness with incomplete pins adds its `UbKind` to
  `Soundness.witnessUndefined` (`ubTailUnverified` for the unanswerable ones),
  so the verdict is not `trusted()`. Set it `false` for 0.9.2's behaviour. It
  is keyed in the cache.
- `ResourceBudget.walkRLimit: uint` (K7), default `1_000_000_000`, `0` opts
  out. It bounds the total Z3 work (units, a step count and not a clock) of
  every check in one walk: each query runs under what is left, and once the
  total is spent the walk stops, the undecided paths are dropped as
  `beBudgetExhaustedPrune` (`sxUnknown`, cap `ckWalkWork`), and a target
  already reached with a sound witness stays a hit. Deterministic, so a walk it
  cuts is the same on every machine, and part of the cache key. The default
  was measured over the whole suite (7818 walks): about 5.7 times the largest
  decided walk, so no decided verdict in the corpus is lost to it. If a large
  SUT now answers `sxUnknown` with `ckWalkWork`, raise it, or set it `0`; it
  bounds work, not wall time (`queryTimeoutMs` still ends a walk first).
  It also counts the walker's own work now (K7 charging): a query's term
  construction and its fact passes are charged to the same spend at 15 units
  per term visit, beside the Z3 units, so a table-heavy walk that spent little
  Z3 work no longer outruns the budget in wall time. A decided walk's spend
  barely moves (the largest walker share in the corpus is 1620 units of
  175.3M), so verdicts that were decided stay decided.

## 4. Verdicts that move

| SUT shape | 0.9.2 | 0.10.0 |
|---|---|---|
| a float -> int conversion of NaN, an infinity or an operand outside the target | a tainted fresh value (`feConvFloatToIntUndefined`), or a trusted `sxSat` on a platform-defined native value (`int(NaN) == low(int)`) | the path halts, `ubFloatToIntRange`: an untrusted `sxUnknown` carrying the kind, no trusted `sxUnsat` over a taint |
| `int8(f)`, `int16(f)`, `int32(f)` with `f` inside the C intermediate (`floatToIntVia`) | undefined | defined and exact: the wrap into the target is modelled (`int8(300.0) == 44`), a trusted verdict. `int64`, `int` and the unsigned targets are one direct cast and unchanged |
| a clean `sxSat` whose path is defined up to the label and undefined after it | trusted | not `trusted()`: `witnessUndefined` (K10b) |
| a callee that divides by an unsigned zero in an opaque body | neither a raise nor a halt | `ubUnsignedDivZero`, and the whole-run gate's second walk halts at the call |
| a stdlib or pragma construct with no admission row | modelled or declined by its own code | declines `feUnadmitted` |
| a `Defect` suppressed by `defectExclusions` on a feasible path | a clean `sxUnsat` | `sxUnknown` with `feDefectExcluded` |
| `float32` <-> `float64` conversion | declined `feFloatWidth` | exact (`fp.to_fp`, round-nearest-even) |
| a host with a Z3 that is not 4.13.4 or 5.1 | ran | declines the run, `feHostUnadmitted` |

The float -> int row is keyed by the C lowering Nim 2.2.10 emits. The
`floatToIntVia` rows (`int8`/`int16`/`int32` targets) are the precision
change: a float inside the intermediate range now decides instead of halting.

## 5. Spend log

`NELLI_WALK_UNITS_LOG=<file>` appends one line per finished walk,
`<units>\t<target>\t<status>\t<walker>`, and `scripts/dt-bounded.sh` forwards
it. The fourth column is the walker's share of `units` (the charge for query
construction and the fact passes, 15 units per term visit; the rest is Z3
work). The whole-run gate's second walk appends its own line beside the explore
walk's, with the target column `k10b-tail` and the status column the `UbKind`
set it returned. A script that reads the file for the maximum spend should skip
or count those lines separately, and a reader that splits on three columns
must accept a fourth.

## 6. The cache cold start

The walker version is `"305"` (was `"287"` in 0.9.2, `"272"` in 0.9.1). Every
0.9.2 entry is orphaned, for three reasons that each suffice: the walker
moved, the settings string lost `arithChecks` and gained `wholeRunDefinedness`
and `budget.walkRLimit`, and the key's build and host half is now one
`buildSegment` (every `BuildSemantics` and `HostSemantics` field) in place of
`|z3=`, `|pcre=` and `|bf=`. The first run after the upgrade recomputes every
verdict. Nothing in your databases is corrupted; stale entries are simply
never read. The history of the bumps is the comment above `symexWalkerVersion`
in `src/nelli/smt/canonicalize.nim`. A CI job that restores a verdict cache
across the upgrade sees no hits on its first run and should expect the cold
cost once.

The soundness codec is unchanged from 0.9.2 (version 4); the set of undefined
kinds is still one decimal integer, now of up to 30 bits.
