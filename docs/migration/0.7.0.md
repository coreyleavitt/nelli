# Upgrading to nelli 0.7.0

`import nelli` no longer re-exports the symex and concolic surface. That is the
break, and unlike 0.8.0's it announces itself: you get compile errors naming
symbols that used to arrive transitively.

Design rationale lives in `docs/rfc/0004-z3-optional.md`. This file is what to
do about it.

> Supersedes the retired per-RFC "downstream audit" format; see
> `docs/migration/README.md` for why that convention was dropped.

## 1. The import surface

`import nelli` used to transitively re-export the entire symex + DSL surface —
`symex.nim` → `choice.nim`, `smt/dsl.nim` → `smt/types.nim`,
`smt/abstraction.nim`, `smt/dsl_parser.nim`, `smt/dsl_typebridge.nim`,
`smt/runtime.nim`, `smt/stdlib_models.nim` → `db.nim`. Any name from that
surface reaching your code through a bare `import nelli` stops compiling.

Run these in your own project. They are a **pre-filter, not the audit**: they
find the call sites faster than the compiler will, but the ground truth is
compiling against 0.7.0.

```sh
grep -rn 'import nelli' --include='*.nim' .

# Named API surface plus the settings/impl types it carries.
grep -rn 'z3FullVersion\|symexFind\|symexForAll\|assertCoveredBy\|concolicCollect\|symexOpaque\|concolicFlip\|SymexProgram\|SymexSettings\|runConcolicFlipImpl' --include='*.nim' .

# Choice-IR surface: the choice constructors re-exported from choice.nim, plus
# IRExprKind and its iek* values re-exported through smt/dsl.nim → smt/types.nim.
grep -rn 'integerChoice\|floatChoice\|booleanChoice\|bytesChoice\|stringChoice\|IRExprKind\|iek[A-Z]' --include='*.nim' .
```

For each file matching either of the last two, check the first: a file with
`import nelli` but no `import nelli/symex` needs the explicit import added.
Treat a clean grep as a lead, not a clearance.

**Not affected:** `symexTarget` / `symexAssert` / `symexAssume` and the
`assertCoveredBy` capture cluster. These moved to `nelli/engine/markers`,
reachable from a bare `import nelli`, precisely so that marker-annotated
production code survives this break untouched. If you annotate your systems
under test, those files need no change.

## 2. Removed `GuidanceConfig` fields

```sh
grep -rn 'stallRounds\|concolicMaxBranchAttempts' --include='*.nim' .
```

- Inside a `GuidanceConfig(...)` literal → **removed**. Migrate to
  `fuzzConcolic(s, p, settings)` and add `import nelli/concolic`.
- Inside an `orchestratorPolicy(...)` call → **unchanged**, leave it. The raw
  orchestrator seam deliberately keeps both knobs.

## 3. The `fuzz` proc's bridge parameter

```sh
grep -rn 'concolicBridge' --include='*.nim' .
```

- `fuzz(..., concolicBridge = b)` →
  `fuzz(..., assist = ConcolicAssist(bridge: b, stallRounds: 1))`
- `newOrchestrator(..., concolicBridge = b)` → **unchanged**.

## 4. Behaviour changes with no compile error

The only items that do not announce themselves. Read these by hand:

- A hand-built `ConcolicAssist` — or a `fuzz` call that relied on a wired
  bridge plus `stallRounds: 0` to stay inert — is now **coerced active**. If a
  call site's intent was "bridge available but disabled", it must now pass
  **no assist at all**.
- A `ConcolicAssist(stallRounds: n)` with no bridge raises
  `ConcolicAssistError` at campaign start rather than running assist-free.

## 5. Toolchain

Unchanged for the base library, and strictly *relaxed* if you do not use symex
or concolic: after 0.7.0 a build that only uses `import nelli` needs no Z3 on
the Nim path at all. If your build passes `--path` entries for z3/softlink
solely to satisfy `import nelli`, they can go.

If you do use `nelli/concolic` or `nelli/symex`, the requirements are what they
always were — Nim ≥ 2.2.10, nim-z3 on the path, libz3 loadable at runtime —
with the softening that a *missing* libz3 now degrades a concolic campaign
instead of aborting it.

## If you are also crossing 0.6.0

0.6.0 carried a breaking `FuzzSettings` regroup and its notes lived only in the
release commit message. `CHANGELOG.md` reconstructs it, and covers both
releases for exactly this reason. Read 0.6.0's entry before this file.
