# Migrating to nelli 0.9.0

This note is version-keyed and consumer-agnostic, like
`docs/migration/0.8.0.md`. It addresses you as the maintainer of a project
that upgrades to nelli 0.9.0. The design behind this release is in
`docs/rfc/0005-branch-scoped-degrade.md` (RFC-0005, "soundness channels").
This file covers what to do; the RFC covers why.

This release changes nelli in three ways, and each needs a different response:

1. **Two contract changes in `nelli/symex`.** These come first because no
   compiler or verdict will point you at them (§1).
2. **Compile breaks.** These announce themselves at the right place (§3).
3. **Verdict changes.** Code that compiles before and after now gets a
   different, more correct answer (§4, §5).

## The one-sentence version

`symexFind`, `assertCoveredBy`, `symexFindAllWitnesses` and `symexForAll` can
now **call your SUT** on inputs the solver chose, so the SUT must link and
load into the calling binary. Each result now says how far to trust it, through
`soundness`, `trusted()`, `gaps()` and `bounds`.

## 1. The contract changes — read these first

### 1.1 `fn` is EXECUTED at verdict time, on solver-chosen inputs

Before 0.9.0, the symex entry points only *read* `fn` at macro time and never
ran it. In 0.9.0 they run it whenever a witness lies on a path that went
through something the analysis could not model, such as an unmodelled call, a
fresh symbol or a `{.symexOpaque.}` proc. Such a witness is a *candidate*:
nelli replays it by calling `fn` with the witness as arguments, and reports
`sxSat` / `sxRaised` only if the real run reaches the target
(`soundness.replay == rsConfirmed`). A refuted or un-replayable candidate is
`sxUnknown`.

What this means for your code:

- **Side effects happen.** The paths that need replay are exactly the ones
  through unmodelled calls, which are often effectful (`echo`, `writeFile`, a
  socket, a sensor read). Replay performs those effects for real, in your
  process, at verdict time. Each replayed candidate runs once, in discovery
  order, and replay stops at the first confirmation. A clean (untainted)
  witness, or a candidate the eligibility gate refuses, runs nothing.
- **Defects.** Under `--panics:on`, every target declines replay, because a
  real run may hit a Defect the model never forked. A `tNilAccess` target
  never replays.
- **Termination.** Replay runs only candidates whose path taint is at most
  `{scSpurious}`, so a path the analysis cut off at a bound is never replayed.
  A replay runs on a thread of its own and is abandoned after
  `SymexSettings.replayTimeoutMs` (default 10_000 ms). The outcome is
  `roTimedOut` and the candidate stays `sxUnknown`, with a `feReplayTimedOut`
  hint. The abandoned thread is left running, because nothing can stop it
  safely, and whatever effects it has still happen. `replayTimeoutMs <= 0`
  runs the replay on the calling thread with no bound, and so does a build
  without `--threads:on`. Either way, a SUT that does not terminate on some
  input is the same risk `forAll` and `fuzz` already take when they call it.

### 1.2 `fn` must LINK and LOAD

Replay needs a real call to `fn` in the generated code. With replay on, `fn`
and everything it calls are compiled, linked and loaded into the binary that
calls the symex entry point, whether or not any candidate is ever replayed.

- An `importc` proc with no definition (a stub you only meant symex to read)
  now **fails the link**.
- A `dynlib` the host lacks now **fails at start-up**. In particular,
  `std/re` loads PCRE1: `libpcre.so.1` on Linux and `pcre64.dll` on x64
  Windows. Most current Linux distributions ship only PCRE2.

No runtime setting can contain either failure, because both happen before any
replay decision runs.

### 1.3 The opt-out

```nim
const noReplay = SymexSettings(replay: false)
let r = symexFind(fn, target, noReplay)
```

`SymexSettings.replay` defaults to `true`. It is read at macro time by every
entry point, so `replay = false` emits no reference to `fn`: nothing is
linked or executed, and every candidate stays `sxUnknown`, which is the
pre-0.9.0 answer for those paths. The setting enters the cache key as
`;rp=off`, and only when it is off, so default-settings cache keys are
unchanged by it.

**Decide per call site:** if `fn` cannot link here, or must never run here,
pass `replay = false`. Otherwise keep the default and accept the side
effects. A mechanical rewrite in either direction is wrong.

## 2. The new surface — what a result now tells you

All additive. None of it changes a status.

| symbol | where | meaning |
|---|---|---|
| `Soundness` | `SymexResult.soundness`, `SymexFinding.soundness` | `pathTaint` (the winning path, `sxSat`/`sxRaised`), `runTaint` (the whole run), `replay` |
| `SoundnessChannel`, `Taint` | | `scSpurious` (the answer may claim something that cannot happen), `scIncomplete` (the run may have missed something) |
| `ReplayStatus` | `soundness.replay` | `rsNotNeeded` (clean path), `rsConfirmed` (replay reproduced the target) |
| `trusted(r)` | `SymexResult`, `SymexFinding` | **the one predicate to branch on**: sat/raised need a clean path or a confirmed replay; unsat needs `scIncomplete notin runTaint`; unknown is never trusted |
| `gaps(r)` | `SymexResult` | per-cause view: each run-tainting error with its `DegradeClass` |
| `SymexFinding.gaps` | `seq[FindingGap]` (`class`, `kind`, `msg`) | the same view on the Z3-free record; a cache hit serves the stored view (empty only for an entry written without it) |
| `DegradeClass` | | the lever: `dcOmitted` / `dcFabricated` → a bound was hit, so raise the budget the message names; `dcFreshSymbol` / `dcSubstituted` → a model gap: model the call, or mark it `{.symexTransparent.}` if it cannot matter; `dcNoAnswer` → a solver resource-out or a walker defect |
| `bounds` | `SymexResult.bounds` (`ResourceBudget`) | the budget the run used. An `sxUnsat` is a proof *under these bounds*. |
| `annotationViolations` | `SymexResult`, `SymexFinding` | a `{.symexTransparent.}` promise found false (`avResultUsed`, `avArgNotInert`), with pragma, callee and site. Verdict-neutral. |

`soundness.runTaint` is the run's join, so a SUT with one opaque call and one
deep loop reads `{scSpurious, scIncomplete}`. Read `gaps()` to find out which
lever to pull. `tests/tsymex_rfc0005_s11_surface.nim` (suite (c)) and
`examples/symex_loops.nim` carry the worked walkthrough.

Every report format renders the findings `Report.symexFindings` holds:

- `ofText`: a `[symex]` section, one line per finding plus one per gap and
  per violation.
- `ofJson`: a `symexFindings` array.
- `ofJunit`: `<system-out>`.
- `ofGithubAnnotation`: an `::error` per annotation violation and a
  `::warning` per untrusted finding.

A report with no symex findings renders exactly as before. If you parse
`ofJson` strictly, allow the new key.

**The cache.** The symex verdict/witness cache now stores each entry's
`Soundness` in the entry's metadata, and a served result carries its stored
`Soundness` unchanged (`fromCache = true`). Replay runs before anything is
persisted: a tainted `sxSat` reaches the cache only after replay confirmed it.
Each entry also stores the run's `gaps()` view, and a hit serves it, so a
cached `sfSat`, `sfRaised`, `sfUnsat` or `sfUnknown` reports the same causes a
cold run would. An entry without that metadata (a third-party writer) is still
a hit, with empty `gaps`. The `saveSymexWitness`, `loadSymexWitnesses`,
`saveSymexVerdict` and `loadSymexVerdict` macros used to discard the database
errors they collected; they now report them, and they reach `Report.dbErrors`.

## 3. Compile breaks

### 3.1 Cache helpers

| before | after |
|---|---|
| `saveSymexVerdict(db, fn, target, settings, status)` | `saveSymexVerdict(db, fn, target, settings, status, soundness)` |
| `saveSymexVerdictImpl(db, prog, target, settings, status, errors)` | `saveSymexVerdictImpl(db, prog, target, settings, status, soundness, errors)` |
| `loadSymexVerdict(...)` / `loadSymexVerdictImpl(...)`: `Option[SymexFindingStatus]` | `Option[CachedVerdict]` (`status`, `soundness`, `gaps`) |
| `loadSymexWitnesses(...)` / `loadSymexWitnessesImpl(...)`: `seq[seq[ChoiceNode]]` | `seq[CachedWitness]` (`choices`, `soundness`, `gaps`) |
| `loadSymexRaisedImpl(...)`: `seq[RawResult]` | `seq[CachedRaised]` (`raw`, `gaps`); each `raw` carries its stored `soundness` |
| `saveSymexVerdictImpl(..., errors)` | gains an optional trailing `gaps: seq[FindingGap] = @[]` (no break) |
| `saveSymexRaisedImpl(..., errors)` | gains an optional trailing `gaps: seq[seq[FindingGap]] = @[]`, one per raw (no break) |

Mechanical fixes: `v == some(sfUnsat)` → `v.isSome and v.get.status ==
sfUnsat`; `w[0]` → `w[0].choices`; `r[0].status` on a raised load →
`r[0].raw.status`. `CachedVerdict` and `CachedWitness` are tuples that gained
a `gaps` field, so a positional unpack such as `let (choices, soundness) = w`
needs a third name, and a tuple literal built in a test needs a third field. Pass `Soundness()` for a verdict you
proved clean, or the `soundness` of the result you are caching.

**Custom `ExampleDatabase` backends.** The symex cache now writes and reads
through `saveWithMetaImpl` and `loadPrimaryWithMetaImpl`. A hand-built
`ExampleDatabase` used with the symex cache must set both. The stock backends
all do. A cache entry that comes back without its soundness metadata is
treated as a miss, and the error is reported on the run. On a hand-built
`ExampleDatabase` whose optional F6 metadata, `secondary`, `corpus` or `sched`
closures are unset, the public wrappers (`save` with `meta`,
`loadPrimaryWithMeta`, `saveSecondary`, `loadSecondary`, `saveCorpus`,
`loadCorpus`, `saveSched`, `loadSched`) now raise `DbError` instead of
calling a nil closure (a SIGSEGV).

### 3.2 Removed or renamed symbols

- `RawResult.pathTaint` → `RawResult.soundness.pathTaint`.
- `ResourceBudget.maxBytesEncodingLen` removed, along with its cache-key
  segment, because the `bytes` model it bounded is gone.
- `SymexErrorKind.heRefVariantUnsupported` removed; a `case` naming it no
  longer compiles. (The ref-variant shapes it declined are modelled now.)
- `rfc0005UnvetoedStatus` → `rfc0005RawStatus`; `decideVerdict`'s `vetoed`
  parameter → `reachUnknown`.

### 3.3 New enum members — an exhaustive `case` needs arms

New `SymexErrorKind` members include `feConvFloatToIntUndefined`
(`dcFreshSymbol`), `heNewFieldZeroUnsupported`, `ceCaptureByRefUnmodelled`,
`eeFinallyReturnOnRaise`, `eeFinallyJumpOnRaise`, `feReplayRefuted` (a hint),
and the RFC-0005 S1b kinds for previously unkinded degrades, and
`feOpaqueEffectHavoc` (`dcFreshSymbol`: an inert opaque call's heap and
raise effects) and `feEvalOrderUnmodelled` (an operand a later call
changes before Nim reads it), `feReplayTimedOut` (a hint: a replay
abandoned past `replayTimeoutMs`), `feTableIterOrder` (`dcFreshSymbol`: a
`for` over a `Table` of two or more entries, walked in a free key order)
and `seRecursiveValueDepth` (`dcNoAnswer`: a recursive value object read
past `maxRecursiveValueDepth`). All are tail-appended.
`ReplayOutcome` gains `roTimedOut`, also tail-appended. Retained for ordinal stability but **never emitted any more**:
`seBytesSymbolicLength`, `seBytesLengthTooLarge`, `hePtrArith`,
`feTransparentResultUsed` and `feTransparentArgNotInert`. The last two moved
to the annotation-violation channel (§2).

### 3.4 Symex IR surface

Code that builds or inspects the symex IR directly needs these; code that
only calls `symexFind` and friends does not. Every symbol below is
reachable through `nelli/symex`, which re-exports `nelli/smt/dsl` (and
through it `types`, `dsl_parser`, `dsl_typebridge` and `runtime`).

- New enum members, tail-appended: `IRTypeKind.itBitSet` (Nim's builtin
  `set[T]`, carrying `bsElemTy`; `itSet` stays `HashSet[T]`),
  `IRExprKind.iekBitSet` (with the new `BitSetOp` enum and `bsOp` /
  `bsArgs`), `IRStmtKind.isSetLen` and `SVKind.svBitSet`. An exhaustive
  `case` over any of them needs an arm.
- New constructors and helpers in `types`: `tBitSet`, `bitSetDomain`,
  `maxBitSetDomain`, `mkBitSet`, `mkSetLenStmt`, `discTagLit`,
  `fieldSplitPointee`, `treeRefPartInContainer`, `hierChain`,
  `boundsCheckSynthWord`.
- `IRExpr` (`iekVar`) gains `vGlobalTy` (a module-level global's declared
  type, nil otherwise) and `vCopy`; `IRStmt` (`isIndex`) gains
  `ixCheckOnly`. New constructor `mkGlobalVar(name, ty, copy = false)`;
  `mkIndexStmt` gains a trailing `checkOnly = false`.
- `mkCall` gains trailing `varLocs: seq[VarLoc] = @[]` and
  `varPtrSafe: seq[int] = @[]`, and `mkClosureCall` gains a trailing
  `varPtrSafe: seq[int] = @[]` (new `VarLoc` tuple type). `mkSeqDel` gains
  a trailing `shift = false` (`seq.delete`, which shifts the tail down).
  Defaults keep existing calls compiling.
- `dsl_parser`: `symexRegisterMethods` / `symexRegisterNoMethods` (method
  dispatch registration), `unregisteredMethodNames`, `implMagic`,
  `varParamMagics` (with `VarMagicModel`), `calleeOuterSyms` and
  `scanProcFieldAssigns`. `dsl_typebridge`: `viewTypeKind` /
  `viewTypeInst` / `viewTypeImpl` and `procValueSymKinds`.
- `runtime`: `readBitSetAs`, `readSeqAs`, `maxWitnessSeqLen`,
  `inheritTagKey`, and the `ptr`-aim witness helpers `ptrAimPrefix`,
  `ptrAimsSnapshot`, `ptrAimsAdopt`, `ptrAimsAt`, `ptrAimPath` and
  `ptrAimInto`.

### 3.5 Moves with no break

`SoundnessChannel`, `Taint`, `DegradeClass`, `SymexAnnotation`,
`AnnotationViolationKind` and `AnnotationViolation` now live in the leaf
module `nelli/smt/soundness`. They are re-exported from `nelli/smt/types`,
`nelli/engine/types` and `nelli/symex`, so existing imports keep working.

## 4. Verdict changes — the headline

- **Over-taint-only `sxUnknown` → `sxUnsat`.** A run whose only gaps could
  make an answer *spurious*, never *incomplete*, now proves `sxUnsat` where
  it used to give up. `trusted()` is true on such an unsat.
- **The two blanket vetoes are gone.** A single `sevError` decline anywhere
  in the run used to force `sxUnknown`. Now a decline matters only on the
  paths it scopes, and a decline that analysis proves unreached is a
  `sevHint` with a suffixed message. A clean witness next to an unreached
  decline is `sxSat`.
- **Replay** (§1) turns tainted candidates into `sxSat`/`sxRaised` when
  confirmed. A refutation is the `feReplayRefuted` hint on an `sxUnknown`.
  `sfReplayMiss` keeps its Phase 14 meaning (a per-seed diagnostic).
- **A walker `sxUnknown` always names a cause.** If the run's errors carry
  no run-tainting entry, a `weInternalWalkerFault` backstop is added, so
  `gaps()` has at least one entry to point at. (Before 0.9.0 the backstop
  fired only on an empty error list, so an `sxUnknown` whose errors were
  all hints or warnings named no cause.)
- **Cache.** Every symex cache entry from 0.8.0 is invalidated by the walker
  version bump. Old entries are orphaned unread, not evicted. They are
  harmless and you may delete them.

## 5. Per-area changes

Each item is a fact about 0.9.0 against 0.8.0. In every item that changes a
verdict, the new verdict is the one Nim's own run of the SUT agrees with, so
the fix is to update the expectation, not to work around nelli.

**Stdlib models (S8c, S8d).**
- Builtin models apply only when the resolved callee is declared in Nim's own
  lib directory. Your own overloads and converters are walked.
- `strutils.replace` is all-occurrence; the old first-match model is
  deleted. On a Z3 build without `str.replace_all`, a `replace` records
  `seZ3VersionMissing` rather than a clean first-occurrence value.
- Type-head models apply only to genuine stdlib types. A user type named like
  a stdlib type is classified by structure, or declined as `sxUnknown` with
  `feUnsupportedParamType`; a user enum gets a real verdict. The `WeakRef` arm
  is gone (Nim's lib has no `WeakRef`).

**Reachability and declines (S9).**
- Unreached anchored declines are `sevHint`, with a suffixed message.
- Twin anchored declines keep one walk record each; dedup keys on message and
  scope.
- A closure reading a `var` capture out of its constructing frame, or one
  whose body writes a capture, records the new `ceCaptureByRefUnmodelled`
  (`dcSubstituted`).

**Names (S8e).**
- A shadowed local's IR name is `name__scN`, and it shows in decline messages
  and cache keys.
- Code that used to abort now walks with recorded declines: generic callees,
  and witnesses of types the caller did not import.
- A `Table`/`HashSet` witness no longer needs `std/tables` or `std/sets` in
  the caller's scope.

**Containers and variants (S8f).**
- `Table`/`HashSet` length is tied to the keys present. Seq witnesses are
  uncapped (the cap was 64) and carry ref-element cells. Table, set and seq
  witnesses render their full contents.
- A branch-changing variant reassignment is `sxRaised FieldDefect`, as in
  Nim 2.
- Arm fields of a runtime-discriminator constructor take their defaults.
- An untouched `float` result binds `0.0`.
- `OrderedTable` and `CountTable` still decline.

**Numeric and string semantics (S8g, S8i).**
- `int(f)` and `intN(f)`/`uintN(f)` no longer raise `RangeDefect`; a
  `try/except RangeDefect` around one is dead code. An out-of-range result is
  fresh (`feConvFloatToIntUndefined`, because the result is C UB). A range
  target such as `Natural(f)` does raise.
- `-low(T)` and `abs(low(T))` raise `OverflowDefect`, and so does
  `low(T) div -1`.
- Paths through `low(T) mod -1` at 32/64 bits (and `div` with overflow checks
  off) end there, so a label reachable only through the trap is `sxUnsat`.
- `RangeDefect` is raised by explicit and implicit int → range/enum
  conversions.
- Signed `mod` and `float(uint64)` follow Nim, so verdicts that depended on
  the old values flip.
- `split(s, "")` is `@[s]`, and `new T` is zero-initialised (`new int`
  reads 0). A field of a `new` object with no clean zero encoding records
  `heNewFieldZeroUnsupported` (`dcFreshSymbol`).
- A slice or `del` defect can change class between `IndexDefect` and
  `RangeDefect`. A string slice raises, and `substr` clamps.
- A deref-write RHS's raise surfaces.
- Reassigning a declined construction is `sxUnknown` with `feUnsupportedOp`,
  where it used to be a walker fault.
- A defect surfaces under any target, so a `tRaisedExn("X")` search can now
  return one of these instead of `sxUnsat`.
- Concolic collection: `branchTrace` gains the handler decisions of a raising
  `if` condition and drops records from handlers the trace never entered.
  `ambiguousBranches` drops for a closure condition that raised.

**Refs and pointers (S8h).**
- Typed ref witnesses carry nil, aliasing and cycles. Each address is one
  object however it is reached, and field values are the input values.
- A `ptr T` witness is a real cell, never freed, where it used to be nil.
- `heapSnapshot` changes:
  - it shows the input heap;
  - it has an entry for every ref position, including positions inside
    by-value params;
  - cells are named breadth-first;
  - `"<max-heap-depth>"` is gone;
  - a variant cell shows its discriminator and active branch;
  - an unobserved scalar pointee has `pointsTo` none, where it was `"0"`.
- Replay treats these witnesses as faithful, so a miss refutes.
- A candidate whose path went through a nil dereference, and any
  `tRaisedExn("NilAccessDefect")` candidate, stays `sxUnknown`
  (`roInconclusive`) instead of running the SUT.

**Control flow (S8j, S8l, S8m).**
- New findings:
  - defects raised in a top-level `return` expression;
  - `RangeDefect` from a narrowing into a signed or `char` target;
  - labels and raises in a `finally` reached by `return`, `break` or
    `continue`;
  - a `finally`'s raise replacing a return;
  - `defer` bodies;
  - code after a labelled `break` out of nested loops, and after a `block`'s
    `break`;
  - each `for` iteration after a `continue`;
  - `FieldDefect` from a branch-changing discriminator write through any ref,
    and wrong-arm `FieldDefect` through a named ref variant, a `ref` alias or
    a ref to a multi-variant.
- Returned values change where a `finally` or `defer` writes `result`.
- Verdicts that flip from false to true:
  - a label in a `finally` left by `continue` (was `sxUnsat`);
  - code reachable only after an inner loop's `break outer` (was `sxSat`);
  - a closure whose bare return yields the zero value.
- Every Z3 error forces `sxUnknown`, never a silent `sxUnsat`; an ill-sorted
  term records `weInternalWalkerFault`.
- New `sxUnknown` causes: `eeFinallyReturnOnRaise` and
  `eeFinallyJumpOnRaise`.
- Witnesses for a named ref variant param are typed by the named ref.

**Resources (S8k).**
- New `ResourceBudget` fields: `maxSeqLen` (default 128) and
  `seqQueryRLimit` (default 20M). Each enters the cache key only when it is
  not the default (`;msl=` / `;sqr=`).
- A witness that needs a string or seq longer than 128 elements is
  `sxUnknown` with `beSolverUndef` naming `maxSeqLen`. It used to be `sxSat`,
  or a hang. Raise `maxSeqLen` to search further.
- A within-cap string query needing more than 20M units is `sxUnknown` with
  `beSolverUndef`. Byte equalities with a constant are decided in character
  form and are much faster.
- A dead label after a concretely bounded loop is `sxUnsat`.
- A `symexAssume` that really bounds a loop records no exhaustion kind.
- `beSolverUndef` messages carry the reason.
- New exports: `symexLoopIterations`, `loopPruneRLimit` and
  `defaultLoopPruneRLimit`.
- New `SymexSettings.replayTimeoutMs` (default 10_000; `<= 0` turns it
  off): the wall time one replay may take (§1.1). It enters the cache key
  only when it is not the default (`;rpt=`). `emitReplayWitness` gains an
  optional trailing `timeoutMs`, and `runReplayBounded` is exported.
- New exported const `maxRecursiveValueDepth = 2` (in
  `nelli/smt/dsl_typebridge`; a constant, not a setting): the levels of a
  recursive value object (`type T = object; kids: seq[T]`) below the
  outermost that are modelled. A read past it declines with
  `seRecursiveValueDepth`.
- New `ResourceBudget.maxRecursionDepth` (default 24; `0` turns it off):
  past `maxCallDepth`, a recursion its arguments bound is followed up to
  this depth, so it reaches its base case instead of declining. A call past
  it declines naming both budgets. It enters the cache key only when not
  the default (`;mrd=`).
- `maxHeapDepth` bounds the depth of a dereference chain (`n.next.next`),
  not the number of dereferences on a path. A SUT that reads one object's
  fields more than `maxHeapDepth` times no longer declines
  `heDepthExhausted`; a path's dereferences are capped at 4096
  (`heapDerefsPerPathCap`, named in the decline).

**Wider modelled fragment (S8n onward).** Many programs that were `sxUnknown`
now get verdicts. They are listed in full in the RFC's §2.5 "As landed"
sections and include:
- callees and closures reading `result` before writing it;
- variant, multi-variant, `distinct`, `array`, tuple, `string` and `seq`
  results;
- variant and tuple field writes and `op=`;
- `s.add(c)` with a char, and `add` on a dotted seq field;
- callees building `Table[string, int]` / `HashSet[int]`, `new(result)` refs,
  and `ref`/`ptr`/table/set results;
- a multi-variant with a `bool` discriminator, or an `else`-covered tag;
- a `seq[uint8]` literal compared against a literal;
- array element writes at constant and symbolic indexes;
- arrays with a nonzero low bound, or indexed by enum/`char`/small ints;
- inline `range` discriminators;
- closure-returning callees;
- integer-element tables and sets;
- uninitialised local arrays, objects, variants and seqs (now `default(T)`).
- `seq` of a `distinct` type, as a local and as a parameter (its witness
  is rendered and replayed);
- a heap `var` / `addr` argument the callee can also reach through a
  global, a capture or another argument's ref, which is now passed by
  reference instead of declining `feUnsupportedOp`;
- an inert opaque call's effects on the heap, globals and captures, and
  the raises it may make (`feOpaqueEffectHavoc`);
- `addr x` of a routine's variable held past the call, and a closure
  applied away from the frame that built it;
- a `seq` of tuple or object elements, `getOrDefault`, `mgetOrPut`,
  `newSeq`, `insert` on an array element or `Table` value, and `for` over a
  `Table` (in a free key order, `feTableIterOrder`);
- `newSeq(s, n)`, `newSeqOfCap` and `newSeqUninit` (whose elements are a
  fresh value, `feUnsupportedOpHavoc`), which aborted the compile. Every
  seq constructor raises `RangeDefect` on a negative length and declines
  one above 2^20 (`feUnsupportedOp`, scoped to that path): an `sxUnsat`
  over an unbounded length needs the length bounded below that;
- `k in {..}` / `k notin {..}` over a set literal of constants, which
  declined;
- in `std/re` patterns:
  - the backtracking verbs and marks;
  - PCRE's start-of-match scan and CRLF start skip;
  - `(*LIMIT_..=0)`;
  - UTF mode;
  - `(?m)` and `(?X)`;
  - `replace` over every such pattern.

  These were undecided or declined. The symex cache key now records
  whether libpcre runs its JIT (`|pcre=`), so a verdict cached under one
  engine is not served under the other;
- a non-operator `{.borrow.}` routine;
- `int(high(int32))` and any widening of a narrower 64-bit literal (they
  faulted);
- a routine's `{.global.}` variable;
- `addr s[i]` of a routine's seq, and `addr` of a case object;
- a call through a proc-valued expression (`t.f()`);
- `std/re` patterns with named groups, inline options, `\p{..}`, newline
  conventions and priority-sensitive alternations, and the captures
  overloads (`=~`, `match` with `matches`, and the rest);
- `var` and `addr` arguments of a call through a proc value, including a
  lambda, a proc field and a generic callee's proc parameter;
- a ref object hierarchy, including up- and down-conversions. A
  down-conversion of the wrong run-time type is `sxRaised
  ObjectConversionDefect`.

`assertCoveredBy` and the `symex` phase accept SUTs with `ref`/`ptr`
parameters, and their `witnessChoices` use a tag encoding. An `Atomic` cell
compiles on cpp.

**Verdicts that were wrong and are now right.**
- A multi-variant input whose discriminator is in an `else` arm is reachable;
  labels behind it were a false `sxUnsat`.
- A callee's variant result binds its `else`-arm fields; labels on them were
  a false `sxSat`.
- A label over an array with a nonzero low bound, over an untouched enum with
  no ordinal 0, or over a `pairs` loop's index could have been a wrong
  `sxUnsat`/`sxSat`. A `pairs` loop's index is now the index, not the
  element.
- Two `var` / `addr` heap arguments that are one cell through different
  refs (`let q = p; setBoth(p.x, q.x)`) were written back in argument
  order, not the callee's: a false `sxSat`.
- An `addr` argument a generic callee stores in a global was modelled as
  a cell for the call only: a false `sxSat`.
- A call-summary cache collision could replay another call's return value.
- `s.add(x)` with `x` an Int-promoted value stored 0: a false `sxUnsat`.
- A call through a proc value (`let f = setBoth; f(x, y)`, a lambda, a proc
  field, a proc passed to a callee) dropped its `var` writes: a false
  `sxSat`.
- A `ptr T` parameter was assumed never to address a ref object's field, a
  global or a `var` parameter of type `T`: a false `sxUnsat`.
- Two raises in one expression were forked in a fixed order instead of
  Nim's evaluation order, and a raise after a rejected regex pattern was
  reachable: a false `sxSat`.
- `inc` / `dec` on any receiver but a bare `int` variable (a field, an
  element) was dropped: wrong verdicts either way.
- An inert opaque call never raised a `Defect`; it now forks each `Defect`
  its body may raise.

**Cache-key changes.** The canonical program form now carries:
- the return type of a value-returning SUT;
- variant field writes;
- uninitialised table and set locals;
- array low bounds (`;lo=`);
- reassignment IR branch grouping;
- width, signedness and range in CFI.

Each landed with a walker bump. The 0.9.0 walker version invalidates all of
them together.

## 6. Checklist

1. For each symex call site, decide whether replay may execute and link `fn`
   (§1). Where it may not, pass `SymexSettings(replay: false)`.
2. Fix the compile breaks (§3).
3. Re-run your symex suites. For each verdict that moved, check it against §4
   and §5. Where you assert `sxUnknown` to mean "unproven", consider
   asserting `not r.trusted` instead: it survives every future precision
   improvement.
4. Where you branch on `r.status == sxSat` / `sxUnsat` to make a decision,
   add `r.trusted`.
