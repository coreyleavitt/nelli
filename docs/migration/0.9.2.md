# Migrating to nelli 0.9.2

A patch release with behaviour changes, so it gets a note. It is Wave 1 of
RFC-0016 (native-parity hardening): the clean false verdicts found by the
2026-11-06 research round (§5.0), and the model of undefined behaviour that
the checks-off work needed. Read `docs/migration/0.9.1.md` first if you are
coming from 0.9.0; this note covers only what moves between 0.9.1 and 0.9.2.
The full list is in `CHANGELOG.md`.

The walker version moves from `"272"` to `"284"` (§5). Several things break a
build (§4): the new `ub*` kinds and `UbKind`, `feLocalPragma`, `feFloatWidth`,
`Soundness.witnessUndefined`, and `--mm:refc`, which is now an error. Two
fields are deprecated (§6). Everything else compiles before and after, which
is why this note exists.

## 1. Verdicts that move

Each row is a shape whose 0.9.1 answer differed from native Nim on the same
build. The 0.9.2 answer is the native one, or a decline where the walker does
not model the native behaviour.

| SUT shape | 0.9.1 | 0.9.2 |
|---|---|---|
| `except T as e:` then `raise e`, or a handler naming a type through an alias; a raise site and a handler that disagreed on the exception type's id | a handler missed, or matched the wrong type | one type id for raise sites and handlers; `raise e` has the static type of `e`. An exact raised value is modelled only for a `let`-bound `newException`; a handler whose type cannot be named declines |
| `--panics:on`: a `Defect` (index, overflow, assertion, ...) inside a `try` with an `except` or `finally` | the arm ran | a known `Defect` ends the process: no `except` arm or `finally` runs. The claim is a crash (`witnessUnsafe` on every crash claim, not only panics ones) |
| `assertCoveredBy`, a witness that reaches the target and then raises a `Defect` the splat has no arm for | the `Defect` unwound out of `assertCoveredBy` and, with no handler above it, ended the process | the target was reached; the call returns its finding. Panics-off only |
| a local `var`/`let` with `{.cursor.}`, `align`, `volatile`, `codegenDecl`, ... | modelled as if it had no pragma (a `{.cursor.}` shared memory the walk copied) | declines `feLocalPragma` on every path that reaches it |
| `x in a .. b`, `x notin a .. b` over an ordinal, including non-constant `..<` bounds | declined | lowers to `a <= x and x <= b`, pinned against native including the boundary |
| `case ... elif` (statement, expression and hoisted forms) | declined | modelled |
| a `seq` field default `@[]` or `@[1, 2]`; a bracket typed `seq[T]` | a bare `[]` reached the parser: a compile stop for an empty default | lowered as a seq literal. Native `var o: T` reads zero; `default(T)`, constructors and `new` apply the defaults, and the walker agrees in every shape |
| a `float32` <-> `float64` conversion, explicit or compiler-inserted | the transparent pass-through: a value of one width flowed on as the other | declines `feFloatWidth` |
| `low(T) mod -1` (and `low(T) div -1` with overflow checks off), 32 and 64 bits | confined the survivor | the path halts, `ubIntMinModMinusOne`. Natively this is SIGFPE on x86-64, never the label |
| unsigned `div` or `mod` by zero | a catchable `DivByZeroDefect` | the path halts, `ubUnsignedDivZero`. Natively SIGFPE; Nim has no check for it |
| signed `+`, `-`, `*` or negation overflowing, overflow checks off | wrapped (two's complement) | undefined: the overflow side is a `ubSignedOverflow` trap, pruned where unreachable, otherwise the path halts. gcc folds `v + 1 > v` to true |
| `{.push overflowChecks: off.}` on a routine | modelled as the settings said | always declines (`feOverflowCheckOption`) in a checking build |
| `{.push overflowChecks: on.}` routine in a checks-off build | the unchecked model | modelled as checked: signed overflow and division by zero raise, whatever the build-derived settings say. Checked-ness is per routine, and a call across the boundary keeps each side's own arithmetic |
| a `{.noinit.}` local read before any write | an unconstrained value, trusted | `ubIndeterminateRead` on the reading path; the verdict is not `trusted()` and is not run in your process |
| a call summary that relied on a pruned undefined side | reused anywhere | reused only where the prune holds |
| a re-executed replay (Windows) of a SUT that names its own routine `{.global.}` | refused: the verdict stayed `sxUnknown` where the POSIX fork confirmed it | confirmed. A global named from another routine stays open |

`SymexSettings.arithChecks` now derives from the build (`arithChecksFor`): a
debug build is all-on, `--overflowChecks:off` drops `acOverflow` and
`acDivByZero` (Nim emits the zero check under `overflowChecks` alone),
`--rangeChecks:off` drops `acRange`. A value you set that disagrees with the
build taints the run `feCheckOption`: the program the build compiles does not
do what the setting says. That is the change to look for first if you set
`arithChecks` to opt out of a check: the opt-out no longer yields a clean
verdict, because on the build it describes the unchecked operation is
undefined, not a defined wrap or a skipped fork.

## 2. The new kinds

All are members of `SymexErrorKind`, tail-appended; the catalogue is
`docs/symex/README.md`, "Declines, taints and undefined behaviour".

- `ubUnsignedDivZero`, `ubIntMinModMinusOne`, `ubSignedOverflow`,
  `ubFloatToIntRange`, `ubIndeterminateRead`: undefined behaviour. The path
  ends at the operation and the omission is recorded on the path
  (`Path.undefined`) and the verdict (`Soundness.witnessUndefined`,
  `undefinedKinds()`). A replay cannot lift it: a witness that reaches the
  target past such an operation is not `trusted()`, and neither
  `symexForAll` nor `assertCoveredBy` runs it in your process.
  `ubFloatToIntRange` is declared and has no emission site yet.
- `feLocalPragma`: a local pragma outside `noinit`, `global`, `inject`,
  `gensym`, `used`.
- `feFloatWidth`: a `float32` <-> `float64` conversion.

## 3. New declines

- A local `var`/`let` with a pragma outside the allowlist (`feLocalPragma`).
- A `float32` <-> `float64` conversion (`feFloatWidth`).
- `{.push overflowChecks: off.}` in a checking build (`feOverflowCheckOption`).
- A handler whose exception type cannot be named.
- `arithChecks` set to something the build does not compile in
  (`feCheckOption`, a taint rather than a path decline).

## 4. Compile breaks

- `SymexErrorKind` gains `ubUnsignedDivZero`, `ubIntMinModMinusOne`,
  `ubSignedOverflow`, `ubFloatToIntRange`, `ubIndeterminateRead`, `feLocalPragma`
  and `feFloatWidth`, and `UbKind* = range[ubUnsignedDivZero ..
  ubIndeterminateRead]` is new. An exhaustive `case` over `SymexErrorKind` needs
  arms for them (the `ub*` kinds are contiguous, so one `of ubUnsignedDivZero ..
  ubIndeterminateRead` arm does it).
- `Soundness` gains `witnessUndefined: set[UbOrdinal]`. A positional or
  exhaustive construction needs the field; `undefinedKinds(s)` reads it as
  `set[UbKind]`. A `SymexFinding` carries it through `soundness`.
- The soundness codec is version 4 (§5). A reader of the encoded string sees six
  fields (seven with `runDependence`) where it saw five; the undefined set is a
  decimal integer of any length, no longer one character per field.
- `--mm:refc` is now a compile error at `import nelli/symex`, naming the build
  field. Under refc nim-z3's `=destroy` hooks do not compile; the error used to
  name `z3/ast.nim` and not the build. Use `--mm:orc` (or `arc`).
- Add an `else` to any `case` on `SymexTargetKind`. It has no new member in this
  release, but the next release adds `stkUndefined`, and an `else` arm is the
  one change that survives it.
- New modules and exports: `nelli/smt/buildprofile` (the build reads and
  `arithChecksFor`/`arithChecksDisagree`), `Path.undefined`, `ArithScope`
  (`asBuild`, `asChecked`) on a routine body.

## 5. The cache

The walker version is `"284"` (was `"272"`) and the soundness encoding is
version 4 (was 3). Every 0.9.1 entry is orphaned: the first run after the
upgrade is cold. The history of the twelve bumps is the comment above
`symexWalkerVersion` in `src/nelli/smt/canonicalize.nim`. Nothing in your
databases is corrupted; stale entries are simply never read.

## 6. Deprecations

Both are removed in 0.10.0 (RFC-0016, INT-39). Nim's `deprecated` pragma takes
no message on an object field, so the warning reads "`arithChecks` is
deprecated" and the path forward is in the field's documentation and here.

- `SymexSettings.arithChecks`: do not set it. The build decides, through
  `--overflowChecks` and `--rangeChecks` (`nelli/smt/buildprofile`). To model
  checks off, build with them off; the unchecked operations are then undefined
  and halt (`ub*`).
- `SymexResult.fromCache`: always `false`; `symexFind` has no cache. The
  cache-hit flag is `SymexFinding.fromCache`, set by `symexFindAllWitnesses`
  and `symexForAll`.

## 7. Known gaps

These are open at the same severity as 0.9.1 or are new precision limits, and
ship listed here (RFC-0016 §2.4).

- **A `sxSat` is trusted on its prefix.** C's undefined behaviour is not
  sequenced, and the walk stops at the first label hit, so it does not see what
  follows the label. A trusted `sxSat` can therefore be one whose path is
  defined up to the label and undefined after it (an unchecked overflow or
  unsigned division by zero on the tail). The undefined operations on the walked
  prefix are caught; the tail is not scanned. The whole-run check is planned
  (RFC-0016 §9.1 item 3, K10b).
- **Destructors during panic unwinding are not modelled** (W1-c2). Under
  `--panics:on` a known `Defect` ends the process; a destructor's side effect
  between the raise and the exit is not walked.
- **Unsigned division in an opaque callee gives no answer** (W1-d1b, K10b). The
  opaque-call scan no longer lists `DivByZeroDefect` for the unsigned division
  magics, and does not yet report "may be undefined" either, so a callee that
  divides by an unsigned zero is neither a raise nor a halt.
- **A checked routine calling an unchecked callee that overflows** declines
  `ubSignedOverflow` (W1-d2c): the callee's own arithmetic is the build's, and
  the overflow is undefined.
- **The halted path records no `undefined` set** (W1-d3): a path that halts at
  an undefined operation ends there, so its own halt is not in
  `Soundness.witnessUndefined`; the set holds undefined operations that a
  surviving path passed. The halt is visible as the path's absence.
- **The re-exec replay and the routine-global rule** (W1-m). On Windows the
  replay re-executes the program; a `{.global.}` named only from another
  routine than the one that declares it stays open, so such a SAT is not
  confirmed there.
- Float-to-int out of range stays `feConvFloatToIntUndefined`; `ubFloatToIntRange`
  has no emission site until K10a.

## Where the native-reproduction property is checked

In 0.9.2 the property that a trusted definite verdict was reproduced natively
is checked by a join (`scripts/k1lite.sh`, `tests/k1lite.nim`) on Linux only:
the c backend in CI, and the cpp backend and Z3 4.13.4 at release, by hand.
Pin records do not yet name the OS or the C compiler, so the mingw and MSVC
rows are pinned by their suites but not joined. Both are Wave 2 (K1a-ci, and
K5a `rowOf`).
