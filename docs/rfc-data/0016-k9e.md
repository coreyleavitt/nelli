# RFC-0016 K9e — pin strength: a mutation run over the walker's arithmetic and raise arms

K9d gave every verdict suite a native pin. A pin can still be weak: it may
pass on a walker that encodes `+` as `-`, compares signed values unsigned, or
never forks an `OverflowDefect`, because no pinned call reaches that arm with
an input that tells the two apart. K9e measures that: it mutates the walker's
integer arithmetic and raise arms one site at a time and asks whether some
pin suite fails. Exit criterion 4: the figure is at or above its floor.

## The pieces

| file | what |
|------|------|
| `scripts/pin-strength-mutants.py` | the generator: `list` the mutants, `show` one, `apply` one to a tree |
| `scripts/pin-strength.sh` | the runner: one scratch copy per mutant, the suites through `dt-bounded.sh`, `P` at once |
| `tests/0016-pinstrength.suites` | the suites the runner runs, in order |
| `tests/0016-pinstrength.tsv` | the committed result (header: sha, counts, figure; one row per mutant) |
| `tests/0016-pinstrength.floor` | the floor, a percentage; only rises |
| `tests/tsymex_0016_k9e_pinstrength.nim` | the check (registered): figure >= floor, header agrees with the rows, a floor above zero needs a complete run, every suite exists and is registered |

`runtime.nim` is never edited in a commit: each mutant is applied to a copy of
the tree's tracked files under the runner's output directory.

## The mutants

Scopes (`SCOPES` in the generator; the last definition of each, so a forward
declaration is skipped): `truncDivInt`, `arithInt`, `cmpInt`, `cmpBV`,
`divBV`, `modBV`, `divisorIsZero`, `overflowCond`, `intBounds`,
`overflowCondInt`, `divLowByMinusOne`, `intWindow`, `wrapIntToWidth`,
`depositSignedOverflow`, `lowerArith`, `lowerCmp`, `lowerConvIntRange`,
`forkAssignRangeCheck`, `lowerExpr`'s `uNeg` arm, and the three
`genRaiseForkDrain` instances for `DivByZeroDefect`, `OverflowDefect` and
`RangeDefect`. Together they are the walker's integer encoding (Int and BV),
its width bounds and wrap, and every deposit and drain of an arithmetic or
range raise.

Rules, each match one mutant, each scope taking only the families that are
encodings there (`FAMILIES`):

- `arith`: `+`↔`-`, `*`→`+` (infix and the backticked operators `binBV` takes);
- `cmp`: `<`↔`<=`, `>`↔`>=`, `==`→`!=`;
- `bv` / `sign`: BV strictness (`bvslt`→`bvsle`, ...), signedness
  (`bvsdiv`↔`bvudiv`, `bvsrem`↔`bvurem`, `bvslt`→`bvult` at a compare,
  `if useSigned:`→`if not useSigned:`);
- `bound`: `low(T)`→`low(T) + 1`, `high(T)`→`high(T) - 1`, a `-1` divisor
  literal → `1`, `(1 shl w) - 1` → `- 2`;
- `logic`: `or`→`and`, a dropped `not` before an `add/sub/mulNo{Over,Under}flow`;
- `defect`: a swapped defect kind at a drain or `routeRaise`
  (`DivByZeroDefect`↔`OverflowDefect`, `RangeDefect`→`OverflowDefect`);
- `drop` (dropped forks): `drop:deposit` (a `<sink>Conds.add c` and the
  `sync...(c)` after it both become `discard c`: the fork is never made in or
  out of a walk), `drop:branch` (a raise, check or wrap guard becomes
  `false and ...`), `drop:force-return` (an early return before a fork always
  taken).

The width-replicated scopes spell one shape at 8, 16, 32 and 64 bits; only the
8- and 64-bit lines are mutated (`WIDTH_REPLICATED`), so one shape is not
counted four times. `doAssert` lines and signatures are not mutated.

**Ids are stable.** An id is `m` + 10 hex of SHA-256 over (scope, rule, the
line's stripped text, that text's occurrence number in the scope, the match
number in the line). No line number enters it: a tree with lines inserted
above every scope lists the same ids (checked when K9e landed). An edit to a
mutated line retires its ids and mints new ones; the generator refuses an id
collision.

At 90792961: **116 mutants** (arith 17, bound 12, bv 6, cmp 20, defect 4,
drop 22, logic 19, sign 16).

## The suites (`tests/0016-pinstrength.suites`)

Eleven registered suites that pin integer arithmetic and its raises natively
(`pinFind`, `pinExact`, `pinCrash`), all green on the base: the compound
operators (`phase15_A1_arithmetic`), overflow at each width
(`phase16_R16_4_overflow`), division by zero signed and unsigned
(`phase16_R16_3_divzero`, `0016_w1d1b_udivzero`), the widths and their
compares (`r6_b2_intwidth`), `RangeDefect` (`phase16_R16_2_rangedefect`),
`low(T) div/mod -1` (`0016_w1d1a_intminmod`), the width-typed Int's overflow
fork (`r6_r3_svint_overflow`), the checks-off wrap and C traps
(`rfc0005_s8aa_remainder_checksoff`), a range subtype's base width
(`162_range_base_width`) and the overflow obligation of a promoted value
(`161_overflow_obligation`). Chosen by the count of arithmetic and raise
words against pin verbs over every pinned `tsymex_*` file. `k9d_pinfind` was
left out: it tests the generator itself, over SUTs chosen for the harness.
The broadest killers run first, since the runner stops at the first failure.

## Statuses and the figure

| status | meaning | counted |
|--------|---------|---------|
| `killed` | a suite failed; `by` is `pin` when the log names `PinFailure` (a K9 verb's native disagreement), `assert` otherwise (the suite's own verdict assertion) | yes |
| `survived` | every suite passed | yes |
| `timeout` | none failed and one hit `SUITE_TIMEOUT` (rc 137) | no; rerun with `IDS` |
| `stillborn` | a compile error in `src/` (Nim or C) | no |
| `equivalent` | the mutant left `runtime.nim` byte-identical | no |

**figure = killed / (killed + survived)**, one decimal. The header also gives
the pin-only count. The runner first runs the suites on the unmutated copy and
aborts if one fails, so a kill is the mutant's.

**A survivor is a finding**, closed one of two ways in the commit that lands
the run: a new pin (a call in one of the suites, or a new suite added to the
list, that the mutant fails), or a recorded equivalent-mutant justification
below (the mutant cannot change any verdict: say why). A survivor is never
answered by lowering the floor.

## Running it

```
P=4 bash scripts/pin-strength.sh /path/to/checkout /path/to/outdir
```

`TREE` is a checkout at the sha measured, with `nim.cfg` and `_deps` (the
runner re-makes each `_deps` link absolute in its copies). The run resumes
from `outdir/results.tsv`. When it ends, `outdir/figure.tsv` is the file to
commit as `tests/0016-pinstrength.tsv`, with the floor raised to its figure.
Env: `P`, `SUITE_TIMEOUT` (600), `BACKEND` (c), `IDS` (a subset),
`SKIP_BASELINE`, `KEEP`; `NELLI_IMAGE`, `NELLI_HOST`, `NELLI_MEM_MB` reach
`dt-bounded.sh`.

## The sample (K9e)

Six mutants at 90792961, `P=3`, on a 6-core host shared with other runs
(`IDS` = the six; the baseline was run separately: all eleven suites green,
53-105 s each). This is the committed `tests/0016-pinstrength.tsv` until the
full run replaces it; it certifies nothing, so the floor stays 0.

| id | mutant | status | by |
|----|--------|--------|----|
| m248f2f17f4 | `OverflowDefect` drained as `DivByZeroDefect` | killed (`phase16_R16_4_overflow`, 136 s) | pin |
| mc532db2980 | BV `<` compared unsigned (`bvslt`→`bvult`) | killed (`phase15_A1_arithmetic`, 104 s) | assert |
| me095e34396 | Int `+` encoded as `-` (`arithInt`) | killed (`r6_b2_intwidth`, 341 s) | pin |
| mf9a40f8296 | Int `<=` encoded as `<` (`cmpInt`) | survived (930 s) | |
| mc9adbbb16d | 64-bit unsigned wrap span `2^32 * 2^32` → `2^32 + 2^32` (`intWindow`) | survived (961 s) | |
| m7494aca7e0 | a signed BV negation loses its `lowerArith` route (no overflow fork for `-low(T)`) | survived (778 s) | |

Figure 3 / 6 = 50.0. The three survivors are findings for the full run's
triage. `arithInt` and `cmpInt` are the Int-sort encoding, which a plain
`int` parameter does not reach (it is a BV); only a width-typed promoted
value or an int-offset local takes it, and `<=` is pinned there by no
suite of the list.

**Cost.** A killed mutant took 104-341 s, a survivor 778-961 s (all eleven
suites, about 75-85 s each with the copy and the container, here under
load). On a 16-core host at `P=4` a suite is about 50-60 s, so a survivor is
about 10 min and a kill 2-4 min: 116 mutants are 2.5-3.5 h if half survive,
under 5 h if all do.

## Survivors no pin has killed

`mc8896d7cd4`, `m1e3bdd1070` and `m5abb679981` sit in `forkAssignRangeCheck`
(`conds.len == 0` early return, the `coRange` gate, the routed defect type).
They are NOT recorded as equivalent: the argument below rests on probes, not
on a proof.

`v = x + y` into a range local takes Nim's hidden range conversion, so
`carriesRangeCheck` keeps `isAssign.aty` nil and the function is not called
(a debug write at its entry never fired for it). It is reached only for an
RHS of the target's own type (`v = f(x)`, `v = p.f`, `v = w` of the same
range type), where Nim inserts no check. Past the bound discharge both probes
reach the `conds` (2 conditions, `coRange` checked) and the raise side is
unsatisfiable on the unmutated tree (`sxUnsat`), because every producer probed
(a ranged param, a call return, a ref field read) is confined to the range.
With the raise side empty, a mutant that drops the fork, the gate, or retypes
the routed raise changes only a redundant survivor constraint or an
unreachable path. A pin would need a value outside the range that Nim does
not check: a `cast`, an uninitialised range local, both of which the engine
declines (`sxUnknown`) today. `tests/tsymex_0016_k9e_kill_ovf.nim` pins the
two reached shapes as `sxUnsat`.
