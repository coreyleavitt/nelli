# RFC-0016 int6-t allowlist: the push regions the opaque defect scan reads through. Line: lib-file:template<TAB>slice<TAB>justification.
# A routine whose typed body holds a check pragma is unreadable to the scan (`check_options.bodyCheckPragma`), whatever expanded it, except a region that is exactly `{.push overflowChecks: off.}` `inc(counter)` `{.pop.}`, expanded from the listed template inside a routine of the template's own toolchain module, identified by the push's position in that module's parsed text (`check_options.loopIncExempt`), never by a name alone. The list must equal `check_options.loopIncExemptions` (tsymex_0016_int6t_typedpush); an entry joins it only with an audit of every use site of its template in the pinned toolchain, and it leaves when the toolchain's template no longer has that shape.
system/iterators.nim:unCheckedInc	int6-t	Audited on 2.2.10 (all 26 use sites, 2026-11-19): every one steps the counter of the loop of a system iterator (items, mitems, pairs, mpairs over openArray, array, set, cstring, seq, string) after that loop's own bound has held for the current value: `while i < len(a)` / `while i < L` (so i < high(int) before the step), `if i >= high(IX): break` for an array (so i < high(IX), and the step stays in IX's range: overflowChecks off drops the range check of `inc` too), `while i <= high(T).int` for a set (a set's element range is at most 0 .. 65535), `while a[i] != '\0'` for a cstring (i indexes bytes of one live object, below high(int)). The step can therefore neither overflow nor leave its range; the region turns off no range, bound, field, object or float check, so reading the routine as one scope loses no Defect and no undefined behaviour.
pure/collections/sequtils.nim:unCheckedInc	int6-u	Audited on 2.2.10 (all 16 use sites, 2026-11-19). Exempt where it expands inside a routine of sequtils itself and steps a local `var` or the routine's `result` (12 sites): `concat` (i < L, the total length, before the step: one step per item written), `cycle` (o < n * s.len, a checked product, before the step), `distribute` (stride = s.len div num with num >= 2, so stride < high(int); last = first + stride below s.len while extra > 0, the pieces summing to s.len), `keepIf` (pos <= i < len(s)), `delete(s, slice)` and the deprecated `delete(s, first, last)` (i < newLen and j - i fixed at j0 - i0, so j < s.len: both steps stay below s.len), `insert` (j + 1 <= max(pos, len(dest)) after the move loop, then one step per item of src with j below the length `i + 1` it set, a checked sum), `count` (int6-w2: `result` starts at 0 and is stepped at most once per item `items(s)` yields, where `items` over an openArray runs `while i < len(a)` over a length fixed at the call; before the step at item k, result <= k < len(s) <= high(int)). Every step is a counter or bound that an earlier comparison or a checked operation holds below high(int), so it cannot overflow; the region turns off no range, bound, field, object or float check, so reading the routine as one scope loses no Defect and no undefined behaviour. NOT exempt: the 4 sites in exported templates (`findIt`, `keepItIf`, `toSeq`, `toSeq2`), which expand into the caller's routine, not one of sequtils; they are bounded the same way (i < the length read, pos <= i), but the rule's owner check excludes them, so a routine using those templates stays unreadable to the scan. The owner check is required, not only conservative (int6-w2): the template is unexported, but `import std/sequtils {.all.}` makes it callable from any module, on any variable, unbounded (tsymex_0016_int6w2_seqtpl), so the push's position at the template body does not by itself place the step at an audited site. A new audited exemption: an addition to the list, not a loosening of its rule.
