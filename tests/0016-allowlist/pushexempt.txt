# A routine whose typed body holds a check pragma is unreadable to the scan (`check_options.bodyCheckPragma`), whatever expanded it, except a region that is exactly `{.push overflowChecks: off.}` `inc(counter)` `{.pop.}`, expanded from the listed template inside a routine of the template's own toolchain module, or (int6-x2) inside any routine when the stepped counter is declared at one of that module's audited counter declarations listed with the entry, identified by the push's position in that module's parsed text and the counter symbol's declaration position (`check_options.loopIncExempt`), never by a name alone. The list must equal `check_options.loopIncExemptions` (tsymex_0016_int6t_typedpush); an entry joins it only with an audit of every use site of its template in the pinned toolchain, and it leaves when the toolchain's template no longer has that shape.
system/iterators.nim:unCheckedInc	int6-t	Audited on 2.2.10 (all 26 use sites, 2026-11-19): every one steps the counter of the loop of a system iterator (items, mitems, pairs, mpairs over openArray, array, set, cstring, seq, string) after that loop's own bound has held for the current value: `while i < len(a)` / `while i < L` (so i < high(int) before the step), `if i >= high(IX): break` for an array (so i < high(IX), and the step stays in IX's range: overflowChecks off drops the range check of `inc` too), `while i <= high(T).int` for a set (a set's element range is at most 0 .. 65535), `while a[i] != '\0'` for a cstring (i indexes bytes of one live object, below high(int)). The step can therefore neither overflow nor leave its range; the region turns off no range, bound, field, object or float check, so reading the routine as one scope loses no Defect and no undefined behaviour.
